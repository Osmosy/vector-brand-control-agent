**Навык агента: что нейросети советуют в вашей категории, кого именно — и почему не вас.**

Канал рекомендаций у ИИ не виден в веб-аналитике: можно быть первым в поиске и отсутствовать
в ответе модели. Навык ставит замер, размечает ответы, считает долю рекомендаций и объясняет
причину выпадения — а не ограничивается вопросом «упоминают ли нас».

**Документация:** [agent-description.md](agent-description.md) ·
[SKILL.md](skills/vector-brand-control-agent/SKILL.md) ·
[набор промптов](skills/vector-brand-control-agent/templates/prompts.csv) ·
[скрипт скоринга](skills/vector-brand-control-agent/scripts/geo_score.py)

## Что это

Процедура GEO-контроля бренда, упакованная как навык Hermes Agent:

1. **Бриф** — бренд, домен, 3–5 конкурентов (латиница и кириллица), гео, факты с источниками
   (`templates/brand.json`).
2. **Набор промптов** — 30 запросов в 6 классах сценариев (category, compare, task, trust, brand,
   risk) с весами (`templates/prompts.csv`).
3. **Замер** — минимум 3 движка, по 3 повтора на промпт: ответы моделей недетерминированы, один
   прогон — не наблюдение.
4. **Разметка** — одна строка на ответ: роль бренда и конкурента, позиция, цитирование
   (`templates/measurements-sample.csv`).
5. **Скоринг** — SoV, win_rate, mention_rate, citation_share, покрытие и топ провальных сценариев
   (`scripts/geo_score.py`).
6. **Диагноз и план** — четыре корзины причин, приоритет правки = вес сценария × частота выпадения.
7. **Динамика** — повторный замер тем же набором промптов и движков через 2–4 недели.

## Что это не

- **Не SEO-аудит.** Позиции в выдаче и техническая оптимизация — другой навык; здесь измеряется
  попадание в текст ответа и в его цитаты.
- **Не генератор контента.** Правки E-E-A-T, структура и schema — следующий шаг; навык говорит,
  что и где править, и даёт базу для сравнения «до/после».
- **Не подписка на сервис.** Измерение делается своими инструментами (Google AI Mode через MCP,
  веб-интерфейсы моделей); платные GEO-сервисы подключаются только с явного разрешения владельца.
- **Не обещание результата.** Навык даёт измерение, диагноз и приоритеты, а не гарантию
  попадания в рекомендации.

## Что измеряется

| Вопрос | Метрика | Знаменатель |
|---|---|---|
| Упоминают ли вообще | `mention_rate` | число ответов, не число промптов |
| Кого советуют вместо | `share_of_voice` (SoV) | рекомендации бренда / рекомендации всех |
| Насколько уверенно | `win_rate` | ответы, где бренд первый или рекомендован |
| Опираются ли на наши источники | `citation_share` | число ответов |
| Где выпадаем | `loss_scenarios` | промпты: конкурент есть, нас нет |

Цитирование и упоминание считаются раздельно: бренд может стоять в источнике, на который
сослалась модель, и не попасть в текст ответа.

## Как это работает

```
brand.json ─► prompts.csv ─► замер: 3 движка × 3 повтора
                                   │
                                   ▼
                   measurements.csv (1 строка = 1 ответ)
                                   │
                     geo_score.py  ▼
      SoV · win_rate · mention_rate · citation_share · покрытие · провалы
                                   │
                                   ▼
            4 корзины причин ─► plan.md ─► повторный замер ─► dynamics.md
```

Ответы сохраняются сырыми (`measurements/raw/`): без сырья разметку не перепроверить, а отчёт о
причинах держится на дословных цитатах.

## Быстрый старт

```bash
git clone https://github.com/Osmosy/vector-brand-control-agent
cp -r vector-brand-control-agent/skills/vector-brand-control-agent ~/.hermes/skills/
```

Проверить скоринг на образце (36 синтетических ответов, 3 движка, 4 промпта):

```bash
python3 skills/vector-brand-control-agent/scripts/geo_score.py \
  --measurements skills/vector-brand-control-agent/templates/measurements-sample.csv \
  --prompts skills/vector-brand-control-agent/templates/prompts.csv
```

Свой замер: заполнить `brand.json`, взять `prompts.csv`, разложить ответы в `measurements.csv`,
прогнать скрипт, получить план правок.

## Ключевые решения и грабли

- **Знаменатель — ответ, а не промпт.** Три повтора на промпт и три движка усредняются по
  ответам; процент «по промптам» скрывает разброс и завышает уверенность.
- **Роль важнее факта упоминания.** «Есть такой сервис» и «берите его» — разные роли
  (`listed` / `recommended` / `top`); без них SoV завышается, а диагноз уезжает.
- **Ответ с веб-поиском отделён от ответа из памяти.** Это разные каналы с разными источниками,
  их нельзя складывать в один тренд.
- **Базовая линия снимается до правок.** Иначе «после» не с чем сравнивать; проверка в чек-листе —
  mtime `measurements.csv` раньше `plan.md`.
- **Набор промптов не меняется между замерами.** Иначе сдвигается знаменатель и «динамика»
  превращается в смену вопроса.
- **Малый срез помечается.** При n < 30 скрипт печатает предупреждение: такой результат идёт
  гипотезой в план, а не вердиктом в отчёт.
- **Числа из промо сервисов — заявление, а не факт.** «>300 компаний», «работает по всем моделям»
  помечаются как заявление и, где можно, проверяются самостоятельно.

## Проверка

```bash
python3 scripts/validate.py                     # состав, ссылки, числа: 0 находок
python3 -m unittest discover -s tests -q        # тесты скоринга
```

CI выполняет те же две команды на каждый push и pull request.
